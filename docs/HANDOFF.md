# Передача контекста: перенос «системы жизни» в Telegram-бота

Документ для другого Claude Code. Источник: репозиторий `dementyevbiz-lab/barbermaxxing-tracker` (Telegram Mini App «Трекер Barbermaxxing»). Читать целиком до начала работы.

## 0. Главные правила

1. В проекте «система жизни» уже есть какие-то свои системы. Их НЕ менять, не переписывать, не «улучшать». Только подключать вход и общие механики рядом.
2. Всё барберское (раздел 3) не переносить и не трогать. Это не часть новой системы.
3. Если нужная механика уже реализована в «системе жизни», её не заменять нашей. Брать из этого репозитория только то, чего там нет.
4. Секреты (токен бота, service_role, пароли) в чат не просить. Токен бота заказчик вставляет сам в секреты функций Supabase (`TELEGRAM_BOT_TOKEN`).
5. Заказчик не программист: объяснять просто, на «вы», вести по шагам.
6. Перед записью секретов и выдачей админ-прав нужно явное разрешение заказчика.
7. Новый проект делать ОТДЕЛЬНЫМ: свой репозиторий, свой проект Supabase, свой бот. Барберский проект не ломать.

## 1. Архитектура (всё бесплатно)

- Фронтенд: статический, без сборки. Ванильный JS, ES-модули, `index.html` + `css/app.css` + `js/`. Хостинг GitHub Pages из `main`.
- База: Supabase (Postgres + RLS, Storage, Edge Functions на Deno, pg_cron + pg_net).
- Telegram Mini App + бот. В боте любое сообщение отвечает кнопкой «Открыть».
- Публичные ключи Supabase лежат в `config.js` (`window.BMX_CONFIG`: supabaseUrl, supabaseKey publishable, botUsername, appUrl). Секретов в репозитории нет.
- Защита от кэша Telegram: `node scripts/stamp.mjs` перед каждой выкладкой (версии файлов и import map в `index.html`).
- Выкладка в Supabase через Management API: `scripts/deploy.sh sql|functions|test|all`. Токен доступа хранится как сетевой секрет окружения, прокси подставляет заголовок сам.

## 2. Что общее и переиспользуемое (брать как основу, если этого ещё нет)

### 2.1 Вход без пароля (самое важное)
- Приложение отправляет Telegram `initData` в Edge Function `tg-auth`.
- Функция проверяет HMAC-SHA256 подпись токеном бота, свежесть `auth_date` до суток (`supabase/functions/_shared/common.ts`, `verifyInitData`).
- Находит профиль по Telegram ID или привязывает одноразовое приглашение `t.me/<бот>?startapp=<код>` (код гасится при входе; «Новая ссылка» отвязывает прошлый Telegram).
- Создаёт или берёт пользователя Supabase и выдаёт обычную сессию через `admin.generateLink` + `verifyOtp` (`issueSession`).
- Итог: `auth.uid()` = `profiles.id`, Telegram ID лежит в `app_metadata.telegram_id`. Аккаунт создаётся с техническим адресом `bmx-<uuid>@example.com` (писем не шлём; если домен не принят, поменять секрет `ACCOUNT_EMAIL_DOMAIN`).
- Роль определяется только на сервере. `is_admin()` сверяет Telegram ID токена с таблицей `admins`.
- Защита от перебора: таблица `auth_attempts` (до 10 неверных кодов в час на аккаунт, 200 всего).
- Клиент: `js/main.js` (`login`, `boot`), `js/core.js` (клиент Supabase с `storageKey: 'bmx-auth'`, `callFn`). Экраны «Доступ по приглашению» и «Нет связи», автоповтор, если база «уснула». Режим проверки вне Telegram только по `#test` с готовой сессией.
- Функция `admin`: create_student, reissue_invite, delete_student, seed_demo, delete_demo, invite_link.

### 2.2 Права (RLS) и защита данных
- Ученик видит и пишет только своё (`user_id = auth.uid()`). Физически ничего не удаляет: только `deleted_at` / `undone_at`.
- Каталоги пользователь только читает. Админ читает всё, кроме личных текстов (в барберском проекте это `insights`, `questions`).
- Закрытый бакет файлов `user_id/…`, ссылки только подписанные.
- Триггеры-стражи запрещают менять чужие и серверные поля (`profiles_guard`, `checkpoints_guard`, `completions_before` и т.д.).
- Тест прав: `supabase/tests/rls_test.sql` (транзакция с откатом). Взять как шаблон.

### 2.3 Опыт, уровни, звания, ачивки (только если в «системе жизни» нет своих)
- Опыт и награды начисляет только сервер: триггеры пишут в `xp_ledger`, пересчитывают ачивки (`recalc_achievements`). Отмена возвращает опыт и снимает ачивки.
- Уровень L при опыте `step·(L−1)·L` (step=50: 100, 300, 600, 1000). Звания по уровням из `settings.ranks`.
- Ачивки открываются по очереди (3 + по одной за полученную, поле `achievements.ord`), подписаны как награды. Ступени дают 10/20/40/80 опыта, правятся в админке.
- Окно «Новое звание» (`showRank`), сверка опыта с сервером (`syncProgress`).
- Лимиты от злоупотреблений: записей в день, окно даты назад.

### 2.4 Клиентские приёмы
- Оптимистичный интерфейс: сначала показать, потом писать в фоне. `write()` с очередью в localStorage при потере связи (`flushQueue`, `startQueueWatch`), клиентские UUID для идемпотентности.
- Запоминание вкладки и прокрутки, перезагрузка данных при возврате в приложение (не чаще раза в минуту).
- Окна (`openSheet`) выезжают снизу, на компьютере по центру. Тост 2 секунды с «Вернуть».
- Чистая логика расчётов в `js/logic.js` с node-тестами (`tests/logic.test.mjs`): удобно тестировать без интерфейса.

### 2.5 Недели, замеры по времени, графики
- Недели открываются по очереди и закрыты на сервере (`max_week`, `item_visible`, политика чтения).
- Замеры открываются по времени (`checkpoint_open`, за 2 дня до срока).
- Графики рисуются только при двух и более точках (`js/charts.js`, `js/pathcard.js`).

### 2.6 Бот и напоминания
- Функция `bot`: вебхук, на любое сообщение кнопка «Открыть».
- Функция `notify`: расписание pg_cron (ежедневно и по часам), таблица `notifications` против дублей, чистый планировщик `_shared/notify.ts` с тестом.
- `scripts/setup-bot.sh` создаёт секреты (`NOTIFY_SECRET`, `BOT_WEBHOOK_SECRET`) и расписание. Запускать только с разрешения заказчика.

### 2.7 Админка (`js/admin/`)
Список пользователей с метками, приглашения, карточка, редактор контента с перетаскиванием, предпросмотром, импортом JSON/CSV, корзиной и историей правок (`audit_log`), бэкап. Брать как образец, если в новой системе нужна админка.

### 2.8 PDF
Итоговый лист на устройстве (html2canvas + jsPDF), скачивание через `Telegram.WebApp.downloadFile`. Нужно, только если заказчик попросит.

### 2.9 Тесты
Локальный Postgres 16 с заглушками Supabase (`supabase/tests/run_local.sh`), deno-тесты подписи и напоминаний, сквозные тесты Playwright на настоящей базе (`tests/e2e/`), автоаудит читаемости (`audit.mjs`): сравнивает цвет текста с фоном и ловит переносы коротких подписей и выход за экран.

## 5. Дизайн-система (оставить структуру, перекрасить)

Структура, сетка, радиусы, шрифт, анимации остаются как в `css/app.css`. Меняется только палитра и подача.

### 5.1 Правила
- Тёмная тема. Все объекты на диагональных градиентах 135°. Плоских заливок и теней нет.
- Шрифт Golos Text (400/500/700). Заголовки блоков заглавными, межбуквенный −0,02em.
- Радиусы: карточки 48, строки 30, кнопки и плашки пилюли, скриншоты 50 с акцентной обводкой.
- Стрелки только треугольниками с градиентом. Эмодзи только значки в строках.
- Анимации 200–300 мс. Окна выезжают снизу.
- Градиентный текст через `background-clip:text`. ВАЖНО: нельзя вешать классы градиентного текста (`.ink/.dim/.limet/.onlime`) на элемент со своей заливкой `background`, текст станет невидимым. Текст кладётся во вложенный `span`.
- Фон: текстура с `filter:brightness(1.3)`, поверх тёмный градиент. `body{background:transparent}`.

### 5.2 Токены: было (лайм) и стало (красно-оранжевая)

| Токен | Было | Предлагаемо |
|---|---|---|
| `--lime` (главный акцент) | #BBFF68 → #F1FF6E | #FF3B1D → #FF8A00 |
| `--lime-dim` (приглушённый) | #3D4A1A → #576624 | #4A1A0F → #7A2E12 |
| `--ink-on-lime` (текст на акценте) | #0F0F0F → #4D4D4D | оставить |
| `--partial` | #FFD95A → #FFB020 | #FFC247 → #FF9F1C (жёлто-янтарный, чтобы отличался от акцента) |
| `--red` (предупреждение) | #F26161 → #D12E33 | сделать темнее и холоднее: #B3202A → #7A1119, чтобы не сливался с акцентом |
| `--bg` | #000 → #1C1E1C | #000 → #1A1412 (тёплый чёрный) |
| `--card` | #3D403D → #1C1F1C | #3A3330 → #1C1715 |
| `--row` | #262626 → #121212 | оставить или #241E1B → #110D0C |

SVG-градиенты в `index.html` (`gLimeBox`, `gLimePath`, `gLimeDim`, `gOnLime`, `gInk`, `gDim`, `gRow`) перекрасить так же. Переименовать `lime` в `accent` везде (CSS, JS, SVG), иначе будет путаница.

Проверить контраст: белый текст на карточках и тёмный текст на красно-оранжевом акценте. Запустить автоаудит `tests/e2e/audit.mjs`.

### 5.3 Тема «Бойцовский клуб» и Тайлер Дёрден
- Текстура фона: гранж, бетон, потёртая краска, трафаретные пятна. Тёмная, приглушённая.
- Заголовки жёсткие, заглавными, как «правила клуба»: «ПЕРВОЕ ПРАВИЛО…», «ТЫ НЕ ТВОЯ РАБОТА». Короткие приказные фразы.
- Номера и счётчики в трафаретном стиле (можно добавить моноширинный или трафаретный шрифт только для цифр и меток, основной оставить Golos Text).
- Мыло, розовая упаковка, значки-ножи не использовать как эмблемы; лучше кулак, трещина, шрам, пятно, штамп.
- Звания в духе клуба (пример): Новобранец, Боец подвала, Член клуба, Инструктор, Проект «Разгром». Заказчик поправит.
- Не цитировать фильм длинными кусками. Короткие собственные формулировки в духе.
- Тексты на «ты», коротко и резко.

### 5.4 Правила текстов
Без длинных тире внутри предложений, без ёлочек в названиях, без конструкции «не X, а Y», без оговорок вроде «не обещание», без точки в конце коротких фраз. Короткие подписи не должны переноситься на вторую строку (`white-space:nowrap`).

6. Перекрасить по разделу 5, прогнать автоаудит.
7. Показать заказчику по одному экрану, до следующего ждать «да».
8. Проверить вживую в Telegram (iPhone, Android, Desktop). Привязка по приглашению в нашем проекте проверена только модульными тестами, в реальном Telegram не проверена.

## 7. Известные грабли

- Класс градиентного текста на элементе с `background` делает текст невидимым (см. 5.1).
- Совпадение имён CSS-классов (`today` у дня календаря и у экрана) ломало вёрстку; использовать `is-today`.
- `node --check` не ловит ошибки в шаблонных строках; проверять `node --experimental-default-type=module --check`.
- Telegram кэширует файлы: без `scripts/stamp.mjs` пользователи видят старую версию.
- GitHub Pages обновляется с задержкой после слияния в `main`.
- Не просить заказчика вставлять токены в чат. Если вставил, сразу попросить отозвать.
