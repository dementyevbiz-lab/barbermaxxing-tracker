# Запуск и проверка

Короткая памятка: как всё устроено, как выкладывать, что проверить на устройствах перед пилотом.

## Как устроено
- Сайт: GitHub Pages, ветка `main`, корень. Адрес в `CLAUDE.md`. Сборки нет: `index.html`, `css/`, `js/`.
- База и функции: Supabase (проект `barbermaxxing`). Схема и данные: `supabase/migrations/`, функции: `supabase/functions/`.
- Выкладка: `scripts/deploy.sh sql|functions|test|all`. Бот и расписание: `scripts/setup-bot.sh` (один раз, создаёт секреты и расписание).
- Секреты функций (в Supabase, не в коде): `TELEGRAM_BOT_TOKEN` (вставляет заказчик), `NOTIFY_SECRET`, `BOT_WEBHOOK_SECRET` (создаёт `setup-bot.sh`).

## Проверки перед выкладкой
```bash
node tests/logic.test.mjs                 # расчёты: уровни, недели, результат, перспектива, триггеры
supabase/tests/run_local.sh               # права и серверная логика на чистом Postgres
deno test --allow-env supabase/tests/     # подпись Telegram и напоминания бота
NODE_USE_ENV_PROXY=1 node tests/e2e/student.mjs   # ученик на настоящей базе (создаёт и удаляет тестовых «E2E …»)
NODE_USE_ENV_PROXY=1 node tests/e2e/admin.mjs     # админка
NODE_USE_ENV_PROXY=1 node tests/e2e/pdf.mjs       # итоговый PDF
NODE_USE_ENV_PROXY=1 node tests/e2e/journey.mjs   # челлендж до награды, пауза, закрытый доступ, вопросы, созвон, корзина, новая ссылка
NODE_USE_ENV_PROXY=1 node tests/e2e/calendar.mjs  # календарь на 7 ширинах экрана, ограничение до января 2027
NODE_USE_ENV_PROXY=1 node tests/e2e/audit.mjs     # автоаудит читаемости: текст против фона на всех экранах и окнах ученика и админа
```

## Проверка на устройствах (делает заказчик, в Telegram)
Для каждого: iPhone, Android, Telegram Desktop на Windows и macOS.
1. Открыть бота, нажать «Открыть». Появляется приложение без экрана входа.
2. Ученик по ссылке-приглашению: онбординг до конца, скриншот из галереи (на компьютере перетаскиванием).
3. Отметить пункт, снять отметку, «Снял видео», записать вывод.
4. Заполнить замер со скриншотами. Размер файла в Supabase: Storage → screenshots (до ~350 КБ).
5. «Профиль → Итог программы (PDF)»: файл скачивается (кнопка активна с последней недели). Если Telegram не скачивает, откроется браузер.
6. Без интернета отметить пункт: «Нет связи, сохраним при подключении», после возврата связи запись доходит.

## Пилот (этап 10)
Неделя с двумя демо-аккаунтами или двумя учениками. Записывать: что не открылось, что непонятно, где тормозит. Критерий: нет блокирующих ошибок, программа наполняется из админки без разработчика.

## Если что-то не работает
- «Обновляем данные»: база уснула или нет связи, подождать минуту. Дважды в неделю её будит `.github/workflows/keepalive.yml`.
- Ученик не может войти: в админке «Новая ссылка» (старая перестанет работать).
- Не приходят напоминания: проверить секреты `NOTIFY_SECRET`, `BOT_WEBHOOK_SECRET`, расписание (`select * from cron.job`), и что ученик разрешил боту писать (при первом входе).
